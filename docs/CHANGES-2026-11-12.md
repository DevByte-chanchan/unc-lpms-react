# Changes — 12 November 2026

Functional requirements added on `feature/course-assignment`, for updating the
functional requirements document. Each line says who can do it and where.

## New functional requirements

**FR — Invite or resend to a Dean (Department List).**
- **Who / where:** the VPAA, on the Department List.
- **Access column:** shows each department's Dean's account status: Not invited yet, Invitation sent, Expired, Failed, Held, or Active.
- **Invite now / Resend:** sends the Dean their set-password invitation.
- **Limits:**
  - at most 5 invitations an hour for one person;
  - current term only;
  - a Dean without a UNC email is held ("Held: …") and not sent.
- **Dean Email:** now kept from the upload and editable in Edit.
- **API:** `POST /api/departments/:id/invite-dean` (VPAA only).

**FR — Invite or resend to an Industry Consultant.**
- **Who / where:** the Program Head, on the Industry Consultant page.
- **Same rules as for the Dean.** A non-UNC email is allowed only for an account that is Industry Consultant only.
- **API:** `POST /api/industry-consultants/:id/invite` (Program Head only). It already existed; the Access label for a sent invitation now reads "Invitation sent".

**FR — Faculty teaching load.**
- **What it computes:** for each faculty member on Active / On Leave assignments:
  - the credit units of the courses they lead this term, across every program;
  - their courses, as Lead and as Contributor;
  - their official sections.
- **Limit:** `MAX_TEACHING_UNITS`, default 24. It is a setting, not UNC policy.
- **API:** `GET /api/course-offering-assignments/load` (Program Head, Dean, VPAA).
- **Status:** the Load dialog and the "would have N units (limit 24)" warning under Lead Faculty were built, then removed from the page on 12 Nov (commit 101ef9c, "remove Load, declutter"). Only the API remains.

**FR — Schedule conflicts in Compare with official offerings.**
- **When:** reading the registrar's Subject Offerings.
- **What it lists:** the same teacher in two classes on the same day at overlapping times.
  - Example: "Harold T. Lim — BIT123L (W 6:30–8:30 PM) overlaps BIT222L (W 6:00–7:30 PM)".
  - The whole file is checked, since a teacher may also teach in another program.
  - It lists conflicts that involve the program being compared.
- **Not counted as conflicts:**
  - back-to-back classes;
  - one class listed twice: the same time and room, or sections of the same course at the same time.
- **Information only:** it never blocks Apply.

**FR — Course Assignment progress strip.**
- **Text:** "N of M courses assigned · N notified · N not notified".
- **What each part counts:**
  - **Assigned:** Active / On Leave rows with a Lead, out of the program's course offerings this term (`GET /api/course-offering-assignments/offered`).
  - **Notified:** rows whose Lead was emailed, told earlier, or has it in their bell.
  - **Not notified:** the rest of the assigned rows.
- **Filtering:** clicking a part filters the table to those rows.
- **Not included:** "learning plans submitted". This module keeps no submission data.

**FR — Exam-date reminders.**
- **When:** 7 days and 1 day before the current term's midterm and final exam dates.
- **Who gets it:** each Lead Faculty of an Active course.
- **What they get:** one bell line and one email listing all their courses: "submit your Learning Plan / TOS for … before <date>".
  - Someone without a password yet gets the bell line only.
- **Never sent twice:** recorded in `deadline_reminders`, with one row per person, term, reminder and date.
- **Settings:**
  - `DEADLINE_REMINDERS=on|off`, default on;
  - `MAIL_MODE` and `MAIL_DEV_ALLOWLIST` still apply.
- **Everyone is reminded:** there is no submission data to skip those who are done.

**FR — Download the final course assignment list.**
- **Who / where:** the Program Head or Dean, from Course Assignment's "⋯" menu.
- **Columns:** Course Code, Course Name, Year Level, Lead Faculty, Contributors, Sections, Status, Date Assigned, Notified. Names are in normal case.
- **Formats:**
  - **Excel:** built by the server.
  - **PDF:** in the UNC form layout (seal, university, program, term, "Page x of y", landscape 330 × 216 mm).
- **File names:** `Course-Assignments_<PROGRAM>_<Term>.xlsx` / `.pdf`.
- **API:** `GET /api/course-offering-assignments/export?format=xlsx|json`.

## Supporting changes (not user-facing requirements)

- **CI:** a GitHub Actions workflow builds, lints and tests on every push and pull request. Server tests run against MySQL, and the run fails if any test is skipped.
- **End-to-end tests:** `npm run e2e` (Playwright) covers sign-in/out, upload and Undo, Add Assignment in a fresh term, Compare, and the Notifications tab.
- **Demo reset:** `npm run demo:reset` puts any non-production database into the demo state.
- **Boot fix:** duplicate indexes are now pruned on every table. `user_accounts` had reached MySQL's 64-key limit and the API stopped booting.
- **ERD:** `erd/lpms-erd-full.drawio` is redrawn from the current schema, with 22 tables including:
  - `account_invitations`, `account_notices`, `notifications`;
  - `course_assignment_history`, `curriculum_documents`, `school_calendars`;
  - `university_statements`, `department_statements`, `import_batches`;
  - `deadline_reminders`, and `departments.dean_email`.
  - `erd/compact/lpms-erd-compact.drawio` is the keys-only version.
